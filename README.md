# Credit Risk Engine

A reproducible credit-risk modeling project for loan-default prediction, with a clear separation between **probability estimation**, **decision policy**, and **explanation/audit**.

> **Status:** The repository is being rebuilt around an independent implementation. The reference figures below are retained from the upstream project for methodological comparison and are **not claimed as results produced by this repository**.

## Problem

Loan-default prediction is an imbalanced classification problem: a useful system must identify risky applications without treating raw accuracy as the primary objective.

This project is structured around:

```text
Applicant data
     |
     v
Validation & data quality
     |
     v
Feature engineering / preprocessing
     |
     v
Risk model -> Probability of Default (PD)
     |
     v
Policy / threshold layer
     |
     +------> Approve
     +------> Review
     +------> Reject
     |
     v
Explanation + audit record
```

The model produces a quantitative risk estimate. The policy layer converts that estimate into an operating decision. Any future LLM/agent component is restricted to orchestration and explanation of verified outputs; it does not generate the credit score itself.

## Dataset

The planned training dataset is **Loan Prediction Based on Customer Behavior** by Subham Jain, available through Kaggle.

It contains applicant-level demographic, financial, employment, housing, and geographic variables with `Risk Flag` as the binary target.

**Dataset:** https://www.kaggle.com/datasets/subhamjain/loan-prediction-based-on-customer-behavior

No model-performance numbers are reported as project results until they are generated by the implementation in this repository.

## Modeling approach

The rebuild will evaluate interpretable and tree-based classifiers using an imbalanced-learning evaluation framework:

- PR-AUC as the primary ranking metric
- default-class recall, precision, and F1
- confusion matrix at the selected operating threshold
- probability calibration
- train/validation/test comparison for overfitting diagnostics
- threshold selection on validation data only
- explicit separation of model probability from business policy

### Planned model workflow

1. Validate schema, types, missingness, duplicates, and target distribution.
2. Create deterministic train/validation/test splits.
3. Apply leakage-safe preprocessing and feature engineering.
4. Train multiple candidate classifiers.
5. Tune the strongest candidates on training data.
6. Select an operating threshold using validation data and documented constraints.
7. Evaluate the locked model once on the held-out test set.
8. Persist metrics and figures as reproducible artifacts.

## Reproducibility standard

A result will only be presented as a project result when the repository contains the code and configuration required to regenerate it. Model selection, threshold selection, and test evaluation will be separated so that the held-out test set is not used to tune the final decision rule.

## Responsible use

This is a research/portfolio implementation, not a production lending system. Credit decisions can materially affect people and require appropriate human oversight, validation, fairness analysis, monitoring, and regulatory review before any real-world use.
